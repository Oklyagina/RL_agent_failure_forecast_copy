# Training Guide

The uncertainty module is policy-agnostic. The Evidential Neural Network (ENN) is trained by behavior cloning on Grid2Op observation/action pairs produced by the configured policy.

Any policy object exposing `act(...)` can be used. For external policies, configure a factory using:

```dotenv
AGENT_NAME=my_agent
AGENT_FACTORY=my_package.my_agent:make_agent
```

The factory receives the Grid2Op environment and returns the policy instance:

```python
def make_agent(env):
    return MyGrid2OpAgent(env.action_space)
```

## Recommended end-to-end path

Run:

```bash
python run_pipeline.py
```

The pipeline validates reusable artifacts and executes the required stages. ENN training uses `data_source="auto"`: configured tutor splits are used when available, otherwise the policy is executed and the behavior-cloning dataset is collected automatically.

## ENN data-source modes

Programmatically:

```python
from src.training_enn import train_enn

train_enn(data_source="auto")     # tutor if available, otherwise rollout
train_enn(data_source="rollout")  # always execute the policy
train_enn(data_source="tutor")    # require tutor files
```

The rollout path does not require tutor output from `curriculumagent`.

## Standalone rollout collection

To collect a behavior-cloning dataset independently:

```bash
python training/collect_rollouts.py \
  --agent-factory my_package.my_agent:make_agent \
  --episodes 50 \
  --out-dir artifacts/my_rollouts
```

For the configured default policy:

```bash
python training/collect_rollouts.py
```

The collector writes:

```text
observations.npy
actions.npy
labels.npy
train.npz
validation.npz
test.npz
```

`actions.npy` contains the distinct action vectors in stable first-observed order. `labels.npy` contains the corresponding action-class index for each observation.

At least two distinct policy actions are required for meaningful ENN training.

## Standalone ENN training from collected rollouts

The lightweight standalone trainer can consume a rollout directory directly:

```bash
python training/train_enn.py \
  --agent-name my_agent \
  --data-dir artifacts/my_rollouts \
  --out-dir artifacts/my_model
```

It exports:

```text
enn_<agent>.pth
scaler_params.json
enn_meta.json
enn_pctile_calib.npz
```

The main pipeline trainer in `src/training_enn.py` exports the broader artifact bundle required by the integrated pipeline.

## ENN objective

The ENN uses an evidential classification objective based on a Dirichlet distribution. The training loss combines Bayes-risk cross-entropy with an annealed KL penalty toward the uniform Dirichlet prior.

The resulting vacuity signal is used as the direct epistemic uncertainty measure:

```text
u = K / S
```

where `K` is the number of retained action classes and `S` is the total Dirichlet strength.

## Calibration

ENN percentile calibration is generated after training and stored in:

```text
enn_pctile_calib.npz
```

The calibration reference maps raw ENN vacuity to relative percentiles used by `recommendation_uncertainty.py`.

For a different reference distribution, use:

```bash
python calibrate_uncertainty.py
```

## Failure classifier

The failure classifier is trained from the contingency dataset generated by the pipeline. It predicts the probability of the failure label used by `src/collect_data.py`.

Classifier artifacts include:

```text
final_classifier_36.pkl
classifier_metadata.json
```

`classifier_metadata.json` defines the feature order, trained line categories, decision threshold, failure class, and training metrics. Keep it with the classifier model.

## Validation

Run:

```bash
python -m compileall -q .
pytest -q
```

For the standalone uncertainty consistency check:

```bash
cd tests
python validate_module.py
```

A live Grid2Op validation requires the target environment dataset and the pinned Grid2Op/LightSim dependency stack.
